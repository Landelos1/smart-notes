# 认证与权限基础模块（已完成）

> 模块目标：将前端认证/鉴权链路与后台权限模型对齐到后端 `/api/common/*` 体系，并打通「登录 -> 获取用户信息 -> 权限生效 -> 退出登录」闭环；同时对齐管理员侧用户列表 `/api/common/users`，保证 `useTable` 可用。

---

## 1. 对齐范围

### 1.1 后端接口对齐

| 功能 | 方法 | 新接口 | 说明 |
| --- | --- | --- | --- |
| 获取验证码 | GET | `/api/common/captcha` | 返回 `captchaId` + `imageBase64` |
| 登录 | POST | `/api/common/login` | 入参：`phone/password/captcha/captchaId/roleType`；返回 token 字符串 |
| 退出登录 | POST | `/api/common/logout` | 需登录 |
| 获取当前用户信息 | GET | `/api/common/user/info` | 需登录，返回 `User` |
| 管理员分页查用户 | GET | `/api/common/users` | Query：`page/size/roleType?/keyword?`；返回 `PageResult<User>` |

### 1.2 权限模型对齐

- **后端角色字段**：`roleType`（仅 1/2）
  - `roleType=1`：普通用户（仅用户端）
  - `roleType=2`：管理用户（可登录用户端 + 管理端）
- **后端登录校验策略**：
  - 登录只校验 `roleType`（普通用户不能用管理端登录）
  - `status=0`（禁用）仍然禁止登录
- **注册状态写入（t_user.status）**：
  - `roleType=1 -> status=1`
  - `roleType=2 -> status=2`
  - 说明：`status` 目前不作为“能否登录后台”的判断条件
- **前端角色枚举（用于 v-roles）**：
  - `roleType=1 -> R_USER`
  - `roleType=2 -> R_ADMIN`
- **前端按钮权限（用于 v-auth）**：以 `roleType` 映射生成 `buttons`（示例：`add/edit/delete/export/view/...`）

### 1.3 多端固定传参约定（重要）

- **管理端（art-design-pro）**：登录/注册固定传 `roleType=2`
- **用户端（note-vue）**：登录/注册固定传 `roleType=1`

## 2. 关键交付物（改动文件）

### 2.1 类型定义

- `src/types/api/api.d.ts`
  - 新增/调整：
    - `Api.Auth.CaptchaVO`
    - `Api.Auth.LoginParams`：使用 `phone/captcha/captchaId/roleType`
    - `Api.Auth.LoginResponse`：仅 `token`
    - `Api.Auth.BackendUser`：对齐后端 `User` 关键字段
    - `Api.Auth.UserInfo`：新增 `phone/roleType` 并承载 `roles/buttons`

### 2.2 API 封装

- `src/api/auth.ts`
  - `fetchGetCaptcha()` -> `/api/common/captcha`
  - `fetchLogin()` -> `/api/common/login`（后端返回 token 字符串，前端包装为 `{ token }`）
  - `fetchGetUserInfo()` -> `/api/common/user/info`（将 `BackendUser` 转成 `Api.Auth.UserInfo`，并完成 `roleType -> roles/buttons`）
  - `fetchLogout()` -> `/api/common/logout`

- `src/api/system-manage.ts`
  - `fetchGetUserList()` -> `/api/common/users`
  - 参数适配：`current -> page`、`size -> size`，并将 `userName/userPhone/userEmail` 折叠为 `keyword`
  - 响应适配：`PageResult<User>` -> `Api.Common.PaginatedResponse<UserListItem>`（返回 `records/current/size/total`，保证 `useTable` 不改动）

### 2.3 页面与交互

- `src/views/auth/login/index.vue`
  - 登录入参改为手机号体系：`phone/password/captcha/captchaId/roleType`
  - 新增验证码图片展示与刷新逻辑

- `src/views/examples/permission/switch-role/index.vue`
  - 示例“切换角色”适配新登录参数：
    - 切换账号时先请求验证码
    - 弹窗输入验证码
    - 再调用登录接口

### 2.4 Store 与登出一致性

- `src/store/modules/user.ts`
  - `setToken(token)` 时显式清空 `refreshToken`（避免旧值残留）

- `src/components/core/layouts/art-header-bar/widget/ArtUserMenu.vue`
  - 用户主动退出：先 `fetchLogout()`，再执行 `userStore.logOut()` 清理本地状态

## 3. 行为变化总结（从“旧链路”到“新链路”）

### 3.1 登录链路

- 登录参数从“用户名体系”切换为：
  - `phone`（11位）
  - `password`
  - `captcha` + `captchaId`
  - `roleType`

- 额外约束：
  - 管理端（art-design-pro）不再提供“角色选择”，固定以 `roleType=2` 登录
  - 用户端（note-vue）固定以 `roleType=1` 登录

### 3.2 Token 存储与请求头

- 请求拦截器会在有 token 时写入：
  - `satoken: <token>`
  - `Authorization: <token>`

### 3.3 权限生效位置

- 路由守卫在需要时拉取用户信息，并写入 `userStore.info`
- `v-roles` 读取 `userStore.getUserInfo.roles`
- `v-auth` 读取 `userStore.info.buttons`（或 route meta）

## 4. 联调/验收步骤（建议）

- **步骤 1：验证码**
  - 打开登录页，确认验证码图片能显示/刷新

- **步骤 2：登录**
  - 输入手机号/密码/验证码登录
  - 管理端固定传 `roleType=2`，用户端固定传 `roleType=1`
  - 登录成功后本地持久化 token

- **步骤 3：获取用户信息与权限**
  - 刷新页面或跳转受保护路由，确认会调用 `/api/common/user/info`
  - `roles/buttons` 正确写入，页面按钮/菜单根据权限显示

- **步骤 4：用户列表（管理员）**
  - 打开用户管理列表页，确认分页/搜索可用

- **步骤 5：退出登录**
  - 点击头像菜单退出，确认先调用 `/api/common/logout`，再跳转登录页

- **步骤 6：构建验证**
  - `pnpm run build` 通过
